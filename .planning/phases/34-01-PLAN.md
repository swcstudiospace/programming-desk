# Plan 34-01: Anomaly Detection & Autonomous Seat Quarantine

## Goal
Implement real-time behavioral anomaly detection, automated seat quarantine state machine, synthetic shadow execution sandbox, dynamic capability pruning, and HMAC-signed federated quarantine attestation receipts.

## Requirements Covered
- **REQ-HEAL-001**: Real-time behavioral anomaly detection engine monitoring tool call latency, payload entropy, and error rate spikes against dynamic baseline profiles.
- **REQ-HEAL-002**: Automated seat quarantine protocol isolating rogue, compromised, or misbehaving seats with deterministic containment states (`HEALTHY` -> `SUSPICIOUS` -> `QUARANTINED` -> `DRAINED`).
- **REQ-HEAL-003**: Synthetic shadow execution sandbox isolating suspicious tool invocations to speculative scratchpads before committing desk mutations.
- **REQ-HEAL-004**: Dynamic capability pruning engine revoking sensitive permissions and execution privileges from degraded seats.
- **REQ-HEAL-005**: Cryptographic quarantine attestation and notification receipts broadcast across federated peer desks with HMAC-SHA256 signatures.

## Proposed Changes
1. **Module `services/desk-gateway/src/desk_gateway/swarm_immune.py`**:
   - `SeatContainmentState`: Enum (`HEALTHY`, `SUSPICIOUS`, `QUARANTINED`, `DRAINED`).
   - `BehavioralAnomalyProfile`: Tracking baseline latency, entropy, error rate with exponential moving averages and standard deviation thresholds.
   - `ToolInvocationTelemetry`: Data structure containing tool call metrics (seat_id, tool_name, latency_ms, payload_entropy, is_error).
   - `SwarmImmuneEngine`:
     - Ingestion of tool execution telemetry and anomaly score computation.
     - Automated state transitions based on anomaly thresholds.
     - Capability pruning logic (reducing allowed scopes from full write/execute down to read-only or no-op).
     - Synthetic shadow execution runner: simulates mutations in an isolated scratchpad buffer, validating safety before promoting or discarding.
     - HMAC-SHA256 quarantine receipts generation and verification.
2. **REST Endpoints in `services/desk-gateway/src/desk_gateway/server.py`**:
   - `POST /v1/immune/telemetry/evaluate`: Evaluate seat telemetry and return anomaly score + containment state.
   - `POST /v1/immune/seat/quarantine`: Explicitly quarantine a seat with audit reason and receipt.
   - `POST /v1/immune/seat/unquarantine`: Restore/rehabilitate a quarantined seat.
   - `POST /v1/immune/shadow/execute`: Run speculative execution in shadow sandbox.
   - `GET /v1/immune/status`: Return overall immune system status and seat states.
3. **Tests in `services/desk-gateway/tests/test_swarm_immune.py`**:
   - Unit tests covering entropy calculation, anomaly detection, threshold breaches, shadow execution, capability pruning, and HMAC verification.
   - Starlette TestClient endpoint tests.
4. **Manifest and Integrity**:
   - Add new files to `.manifest.json` and verify quality gates.
