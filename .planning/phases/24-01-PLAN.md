# Plan 24-01: Cross-Substrate Continuous State Mirroring & Fast RPO Sync

**Milestone:** v2.9 - Cross-Cloud Disaster Recovery & Multi-Substrate Replication  
**Phase:** 24 - Cross-Substrate Continuous State Mirroring & Fast RPO Sync  
**Requirements:** `REQ-DR-001`, `REQ-DR-002`, `REQ-DR-003`, `REQ-DR-004`, `REQ-DR-005`

## Goal
Implement a cross-cloud multi-substrate state mirroring and disaster recovery synchronization engine in `desk-gateway`:
1. Continuous asynchronous state mirroring across primary and secondary data substrates (`REQ-DR-001`).
2. Delta snapshotting with cryptographic block checksums (SHA-256) and incremental catch-up replication (`REQ-DR-002`).
3. Replication lag monitor with dynamic throttle adaptation under WAN congestion (`REQ-DR-003`).
4. Atomic cross-substrate state cutover harness ensuring zero data loss (RPO = 0) (`REQ-DR-004`).
5. Standby health polling and automated warm-replica promotion readiness verification (`REQ-DR-005`).

## Implementation Tasks
1. **Module `services/desk-gateway/src/desk_gateway/disaster_recovery.py`**:
   - `ReplicaState`: Enum (`SYNCING`, `WARM_STANDBY`, `PRIMARY`, `PROMOTING`, `DEGRADED`).
   - `SubstrateDeltaBlock`: Dataclass capturing block index, previous block hash, block hash, timestamp, payload dict, and size bytes.
   - `SubstrateStateMirrorEngine`:
     - Append delta blocks to primary log.
     - Replicate blocks to registered warm standby replicas.
     - Measure replication lag (block count delta and latency in ms).
     - Adaptive throttling when lag exceeds configurable ceiling.
     - Zero data loss atomic cutover: sync remaining uncommitted blocks before transferring primary role (RPO=0).
     - Warm standby readiness probe checking replica parity and block integrity.
2. **Gateway Endpoints in `server.py`**:
   - `POST /v1/dr/mirror/block`: Submit delta block to primary substrate log.
   - `GET /v1/dr/mirror/status`: Fetch replication lag, active replicas, and throttling state.
   - `POST /v1/dr/replica/register`: Register secondary standby replica.
   - `POST /v1/dr/replica/sync`: Catch up replica with missing delta blocks.
   - `POST /v1/dr/cutover`: Execute atomic cutover to target replica with zero data loss verification.
3. **Tests & Verification**:
   - `services/desk-gateway/tests/test_disaster_recovery.py`:
     - Test block chaining, cryptographic checksums, and delta catch-up.
     - Test replication lag calculation and adaptive WAN throttling.
     - Test atomic cutover with RPO=0 verification.
     - Test standby health polling and replica promotion.
     - Test FastAPI / Starlette endpoints via TestClient.
4. **Gates**:
   - G-1 through G-7 verified clean.
