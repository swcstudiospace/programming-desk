# Plan 25-01: Automated Split-Brain Protection, Fencing Tokens & Fast RTO Recovery

**Milestone:** v2.9 - Cross-Cloud Disaster Recovery & Multi-Substrate Replication  
**Phase:** 25 - Automated Split-Brain Protection, Fencing Tokens & Fast RTO Recovery  
**Requirements:** `REQ-DR-006`, `REQ-DR-007`, `REQ-DR-008`, `REQ-DR-009`, `REQ-DR-010`

## Goal
Implement split-brain prevention, fencing tokens, quorum heartbeat evaluation, deterministic vector clock conflict reconciliation, sub-second RTO recovery, and DR drill auditing in `desk-gateway`:
1. Distributed fencing token allocator preventing split-brain writes during failover (`REQ-DR-006`).
2. Automatic quorum heartbeat evaluator isolating partitioned primary clusters (`REQ-DR-007`).
3. Deterministic state conflict reconciler using vector clock ordering (`REQ-DR-008`).
4. Fast failover recovery orchestrator achieving sub-second recovery time objectives (RTO < 1s) (`REQ-DR-009`).
5. End-to-end disaster recovery drill verifier generating non-repudiable audit receipts (`REQ-DR-010`).

## Implementation Tasks
1. **Module `services/desk-gateway/src/desk_gateway/split_brain_recovery.py`**:
   - `FencingToken`: Monotonically increasing epoch number with cluster generation ID.
   - `FencingTokenAllocator`: Issues and validates fencing tokens, rejecting stale or split-brain requests.
   - `QuorumHeartbeatEvaluator`: Tracks heartbeat timestamps across nodes; triggers cluster isolation if quorum drops below floor (> 50%).
   - `VectorClockReconciler`: Reconciles diverging state logs using vector clock comparison (concurrent conflict resolution).
   - `FastFailoverOrchestrator`: Executes sub-second failover (RTO < 1s) with fencing token epoch step and quorum election.
   - `DisasterRecoveryDrillVerifier`: Simulates primary node failure, runs drill, measures RTO, and generates cryptographic drill receipt.
2. **Gateway Endpoints in `server.py`**:
   - `POST /v1/dr/fencing/allocate`: Allocate next fencing token epoch.
   - `POST /v1/dr/fencing/validate`: Validate fencing token against current generation.
   - `POST /v1/dr/quorum/heartbeat`: Record node heartbeat and evaluate quorum state.
   - `POST /v1/dr/reconcile`: Reconcile conflicting state deltas with vector clocks.
   - `POST /v1/dr/drill/run`: Execute automated disaster recovery drill and return signed receipt.
3. **Tests & Verification**:
   - `services/desk-gateway/tests/test_split_brain_recovery.py`:
     - Test fencing token monotonicity and rejection of stale tokens.
     - Test quorum heartbeat drops triggering cluster partition isolation.
     - Test vector clock conflict resolution.
     - Test sub-second RTO failover execution (< 1000ms).
     - Test drill verification and cryptographic receipt generation.
     - Test Starlette API endpoints via TestClient.
4. **Gates**:
   - G-1 through G-7 verified clean.
