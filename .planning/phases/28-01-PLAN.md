# Plan 28-01: Dynamic MCP Tool Mesh Registry & Capability Scopes

**Milestone:** v3.1 - Model Context Protocol (MCP) Dynamic Mesh & Cross-Desk Remote Tool Invocation  
**Phase:** 28 - Dynamic MCP Tool Mesh Registry & Capability Scopes  
**Requirements:** `REQ-MCP-001`, `REQ-MCP-002`, `REQ-MCP-003`, `REQ-MCP-004`, `REQ-MCP-005`

## Goal
Implement a dynamic Model Context Protocol (MCP) tool mesh registry with capability discovery, seat permission scoping, foreign schema translation, rate limiting, and circuit breaker protection in `desk-gateway`:
1. Dynamic MCP server capability discovery and registration across federated desks (`REQ-MCP-001`).
2. Fine-grained per-seat tool permission schemas and capability scoping (`REQ-MCP-002`).
3. Dynamic schema translation and validation for foreign tool descriptors (`REQ-MCP-003`).
4. Rate-limiting and concurrent tool execution quotas per MCP server connection (`REQ-MCP-004`).
5. Health monitoring and automatic circuit breaker for degraded remote MCP endpoints (`REQ-MCP-005`).

## Implementation Tasks
1. **Module `services/desk-gateway/src/desk_gateway/mcp_mesh.py`**:
   - `MCPToolDescriptor`: Model for registered tool (tool name, description, input schema, output schema, required capabilities, server ID).
   - `MCPServerEndpoint`: Model for MCP server connection (server ID, host, transport type, capabilities list, active jobs, max concurrency, rate limit, circuit state, consecutive failures).
   - `SeatPermissionScope`: Model mapping seat IDs to allowed tool name patterns, allowed argument schemas, and max daily execution quotas.
   - `DynamicMCPToolMeshRegistry`:
     - Register remote/local MCP server and discover advertised tools (`register_server`, `register_tools`).
     - Dynamic schema translation and normalization (`normalize_tool_schema`, `validate_arguments`).
     - Seat capability authorization check (`authorize_seat_tool_call`).
     - Acquire and release execution slot with rate limiting & concurrency quotas (`acquire_execution_slot`, `release_execution_slot`).
     - Server health monitoring and circuit breaker trip/reset (`record_server_failure`, `record_server_success`, `reset_server_breaker`).
2. **Gateway Endpoints in `server.py`**:
   - `POST /v1/mcp-mesh/server/register`: Register MCP server and its tool list.
   - `GET /v1/mcp-mesh/tools`: List discoverable tools filtered by seat permissions.
   - `POST /v1/mcp-mesh/tools/authorize`: Check if a seat is authorized to invoke a tool with specific parameters.
   - `POST /v1/mcp-mesh/slot/acquire`: Acquire rate-limited execution slot.
   - `POST /v1/mcp-mesh/slot/release`: Release execution slot.
   - `POST /v1/mcp-mesh/server/failure`: Record endpoint failure and evaluate circuit breaker.
   - `GET /v1/mcp-mesh/status`: Aggregate status of servers, tools, and circuit states.
3. **Tests & Verification**:
   - `services/desk-gateway/tests/test_mcp_mesh.py`:
     - MCP server and tool registration with schema normalization.
     - Seat capability scoping (allowed vs denied tool invocations).
     - Argument validation against translated JSON schemas.
     - Concurrency limits and rate limiting rejection.
     - Circuit breaker tripping upon consecutive failures and fallback/fast-fail.
     - Gateway Starlette endpoints via TestClient.
4. **Gates**:
   - G-1 through G-7 verified clean.
