# Phase 39 Plan 01: Multi-Tenant Sovereign Enclaves & Attested Data Fencing

## Context & Objective
Implement cryptographically isolated multi-tenant sovereign enclaves within the Programming Desk mesh. Prevent cross-tenant memory, context, and tool execution leakage through strict boundary isolation. Provide zero-knowledge token masking and PII redaction for cross-desk payloads. Establish a Tenant Key Encapsulation Mechanism (KEM) generating distinct tenant-specific cryptographic signing keys and encryption roots with per-tenant lifecycle rotation. Enforce attested data fencing policies checking data residency, compute tenancy tiers, and egress controls, verified by an end-to-end enclave breach benchmark suite.

## Implementation Steps
1. Create `services/desk-gateway/src/desk_gateway/sovereign_enclaves.py`:
   - `TenantSovereigntyProfile`: Data structure defining tenant ID, residency region, allowed seats/desks, compute tier, encryption key ID, and fencing rules.
   - `ZKTokenMasker`: Zero-knowledge token masking and PII sanitization pipeline (redacting tokens, API keys, emails, IPs, custom patterns) with reversible tokenization map per enclave session.
   - `TenantKeyEncapsulationMesh`: Generates distinct tenant signing and AES/HMAC cryptographic roots with versioning and dynamic rotation.
   - `AttestedDataFencingEngine`: Validates whether a given task, data transfer, or tool call adheres to tenant residency, allowed egress regions, and compute restrictions; issues HMAC-signed fencing decisions.
   - `SovereignEnclaveManager`: Manages enclave sandboxes, enforces isolation boundaries across concurrent tenant executions, and tracks breach events.
   - `EnclaveBreachSimulator`: Benchmark harness testing isolation under concurrent adversarial cross-tenant access attempts.
2. Integrate into `services/desk-gateway/src/desk_gateway/server.py`:
   - Add routes:
     - `POST /v1/enclaves/tenant/register`
     - `POST /v1/enclaves/mask`
     - `POST /v1/enclaves/unmask`
     - `POST /v1/enclaves/fencing/evaluate`
     - `POST /v1/enclaves/key/rotate`
     - `POST /v1/enclaves/breach-test/run`
3. Implement test suites:
   - `services/desk-gateway/tests/test_sovereign_enclaves.py`
   - `services/desk-gateway/tests/test_sovereign_enclaves_gateway.py`
4. Run all quality gates (G-1, G-3, G-7) and full pytest suite.
