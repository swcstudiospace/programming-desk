# Plan 19-01: LLM Tier Routing & Cost-Aware Model Optimization

## Objective
Implement complexity-aware task classification, dynamic fallback cascades, prompt caching optimization, performance/cost benchmarking, and continuous FinOps verification to optimize token consumption and cost across model tiers (`REQ-TIER-001` through `REQ-TIER-005`).

## Requirements
- `REQ-TIER-001`: Complexity-aware task classifier routing work to optimal LLM cost tiers (Tier 1: Fast/Small, Tier 2: Mid/Standard, Tier 3: Reasoning/Frontier).
- `REQ-TIER-002`: Dynamic fallback cascade automatically degrading or upgrading model tiers on provider rate limits (429), timeouts, or budget exhaustion.
- `REQ-TIER-003`: Cache-aware prompt optimizer detecting repeated prompt prefixes and semantic memory context to maximize prompt caching hit rates (>60%).
- `REQ-TIER-004`: Model performance & cost-efficiency benchmarking monitor tracking latency, completion quality, and tokens-per-dollar across tiers.
- `REQ-TIER-005`: Continuous FinOps verification test suite ensuring RPO=0 on spend tracking, sub-millisecond routing overhead (<5ms), and strict budget cutoff enforcement.

## Architecture & Design
1. **Module `tier_routing.py` in `desk-gateway`**:
   - `LLMTier` (Enum: `TIER_1_FAST`, `TIER_2_STANDARD`, `TIER_3_REASONING`).
   - `ComplexityClassifier`: Evaluates task attributes (input token length, structural complexity score, code generation / reasoning keywords, multi-turn context) and determines tier:
     - Tier 1: Fast/Small (e.g. `gpt-4o-mini`, `claude-3-5-haiku`) for routine status checks, formatting, short summaries.
     - Tier 2: Standard/Mid (e.g. `claude-3-5-sonnet`, `grok-2`) for standard code generation, tool coordination, review.
     - Tier 3: Reasoning/Frontier (e.g. `deepseek-reasoner`, high-complexity frontier) for mathematical proofs, complex architecture synthesis, deep debugging.
   - `FallbackCascadeManager`: Models cascade paths per tier. On provider error (HTTP 429, timeout, budget exhaustion, circuit breaker trip), dynamically routes to fallback models across tiers or cross-providers.
   - `PromptCacheOptimizer`: Splits prompts into static system/context prefix and dynamic suffix, computes SHA-256 prefix signatures, evaluates prefix reuse across calls, and aligns prompt tokens along cache boundaries to exceed 60% hit rate.
   - `TierBenchmarkMonitor`: Tracks request latencies, cost per request, completion quality scores, and computes tokens-per-dollar metrics per model/tier.
   - `FinOpsVerifier`: Runs verification drills validating RPO=0 on spend recording, sub-millisecond routing overhead (<5ms), and immediate enforcement of budget circuit breaker cutoffs.
2. **Server Integration (`server.py`)**:
   - Initialize `ComplexityClassifier`, `FallbackCascadeManager`, `PromptCacheOptimizer`, `TierBenchmarkMonitor`, and `FinOpsVerifier` on gateway app.
   - Expose REST endpoints:
     - `POST /v1/finops/tier/classify`: Classify task complexity and recommend tier/model.
     - `POST /v1/finops/tier/fallback`: Resolve fallback cascade candidate on failure condition.
     - `POST /v1/finops/cache/optimize`: Analyze prompt and generate cache prefix metadata and hit statistics.
     - `GET /v1/finops/benchmark`: Return tier performance and tokens-per-dollar metrics.
     - `POST /v1/finops/verify`: Run continuous FinOps verification drill and report results.
3. **Tests (`tests/test_tier_routing.py`)**:
   - Unit tests for classifier thresholds and routing recommendations.
   - Fallback cascade transitions on 429, timeout, and budget exhaustion.
   - Cache optimizer prefix matching and >60% hit rate demonstration.
   - Benchmark tracking and tokens-per-dollar calculations.
   - Continuous FinOps verification validating RPO=0, latency overhead < 5ms, and hard cutoffs.
   - Integration tests with REST endpoints on TestClient.

## Verification Gates
- `G-1`: Sub-millisecond routing overhead (<5ms target, validated <1ms in benchmarks).
- `G-2`: Dynamic degradation on circuit breaker trip.
- `G-3`: Prompt caching hit rate exceeds 60% on recurring prefixes.
- `G-4`: Full suite passes `uv run pytest` and root gate tests.
