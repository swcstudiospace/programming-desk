# Plan 26-01: Ephemeral Seat Enclave Credentials & Dynamic Mutual TLS

**Milestone:** v3.0 - Continuous Zero-Trust Compliance & Cryptographic Enclave Attestation  
**Phase:** 26 - Ephemeral Seat Enclave Credentials & Dynamic Mutual TLS  
**Requirements:** `REQ-ZERO-001`, `REQ-ZERO-002`, `REQ-ZERO-003`, `REQ-ZERO-004`, `REQ-ZERO-005`

## Goal
Implement a continuous zero-trust security and enclave attestation engine in `desk-gateway`:
1. Ephemeral per-seat session credential issuer with micro-TTL token expiry (`REQ-ZERO-001`).
2. Dynamic mutual TLS (mTLS) certificate authority for inter-seat and inter-desk communication (`REQ-ZERO-002`).
3. Hardware/enclave attestation evidence verifier evaluating cryptographic measurement claims (`REQ-ZERO-003`).
4. Zero-trust continuous authentication policy engine re-verifying seat posture on sensitive tool calls (`REQ-ZERO-004`).
5. Instantaneous session revocation & certificate revocation list (CRL) distribution across edge nodes (`REQ-ZERO-005`).

## Implementation Tasks
1. **Module `services/desk-gateway/src/desk_gateway/zero_trust.py`**:
   - `EnclavePosture`: Enum (`HEALTHY`, `DEGRADED`, `COMPROMISED`, `REVOKED`).
   - `AttestationReport`: Model capturing PCR/measurement hash, platform nonce, enclave signature, and timestamp.
   - `EphemeralCredential`: Model for micro-TTL token (expires in 60s by default) with HMAC signature.
   - `SeatCertificate`: Model for mTLS seat cert (serial number, valid from/to, seat ID, public key hash, fingerprint).
   - `ZeroTrustEnclaveManager`:
     - Issue and validate ephemeral credentials (`issue_ephemeral_token`, `validate_ephemeral_token`).
     - Issue and verify seat mTLS certificates (`issue_seat_cert`, `validate_cert`).
     - Verify hardware/enclave attestation measurement against expected golden hashes (`verify_attestation_report`).
     - Continuous posture re-check for sensitive actions (`evaluate_tool_invocation_posture`).
     - Revocation & CRL management (`revoke_session_or_cert`, `is_revoked`, `get_crl`).
2. **Gateway Endpoints in `server.py`**:
   - `POST /v1/zero-trust/token/issue`: Issue ephemeral micro-TTL token.
   - `POST /v1/zero-trust/token/validate`: Validate ephemeral token.
   - `POST /v1/zero-trust/cert/issue`: Issue seat mTLS certificate.
   - `POST /v1/zero-trust/attestation/verify`: Verify enclave measurement attestation.
   - `POST /v1/zero-trust/posture/evaluate`: Evaluate continuous posture for tool call.
   - `POST /v1/zero-trust/revoke`: Revoke token or cert serial and update CRL.
   - `GET /v1/zero-trust/crl`: Fetch current Certificate Revocation List.
3. **Tests & Verification**:
   - `services/desk-gateway/tests/test_zero_trust.py`:
     - Micro-TTL token issuance and expiry validation.
     - mTLS certificate issuance and validation.
     - Enclave attestation verification with valid vs invalid measurement.
     - Continuous posture evaluation and step-up requirements.
     - CRL revocation and instant denial.
     - Starlette API routes via TestClient.
4. **Gates**:
   - G-1 through G-7 verified clean.
